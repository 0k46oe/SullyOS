# 真实定位与隐私区域

实时感知主页面只放「真实定位」开关和「设置与预览」入口。进入真实定位子页后，才能选定位方式、打开「隐藏地点」「高德 API」「定位说明」以及查看位置预览；隐私说明和隐藏前后的例子都在「定位说明」中。预览按钮先保存当前定位设置，再取得本次位置；使用实际 user 名称和真实请求共用的位置提示词，默认只展示位置句，完整提示词折叠显示。修改定位设置或 user 名称后清除旧预览；进入页面本身不触发定位。

子页面暂时隐藏其它实时感知设置；高德页提供直达官方控制台申请 Key 的按钮、图文说明链接和三步指引。「返回真实定位」保留草稿，「保存并返回」校验并保存本机定位配置。全局返回／浏览器和 Android 返回先从隐藏地点等子页退到真实定位，再退到实时感知；正在取得位置时暂时禁止返回，避免丢掉正在记录的地点。

高德输入框上方高亮提示平台必须选「Web服务」，不能选「Web端（JS API）」；输入框提供显示／隐藏按钮，离开高德页后恢复隐藏。粘贴 Key 后自动选用高德。定位失败原因直接显示在预览区，设备权限／取坐标失败与高德 Key／网络错误分别说明；只使用固定解释，不回显服务商原始响应、Key 或坐标。新增定位功能调用设备接口时关闭原生错误日志；其它定位调用保留原行为。

设置 → 实时感知 → 真实定位 → 设置与预览。默认关闭。「免费 · 大概地区」无需 API Key；「高德 · 街道和附近地点」需要用户自己的高德 Web 服务 Key（[申请步骤](https://lbs.amap.com/api/webservice/create-project-and-key)），不要用 Web 端 JS API Key。先设置隐藏地点，再开启并保存；「把当前位置设为隐藏地点」只读取设备坐标，不查询地图。首次定位需允许浏览器／系统定位权限，网页需 HTTPS（本机 localhost 可用于开发）。

隐私区域可命名为「家」「公司」等别名，并指定 WGS84 中心点和 0.1–100 公里半径，最多 12 个。多圈重叠时按列表先后选第一圈；设备精度误差范围触及隐私圈时也按隐私区域处理。不要用真实门牌地址作别名。

## 数据流与边界

1. 前台实时互动获得设备定位；每轮取得新定位，再匹配本机隐私圈，不依赖先前查到的地址。
2. 命中隐私圈：不发起任何地点查询。提示词的位置只用「家附近」这样的别名；边界不确定时标注可能在家附近。不传半径、中心坐标或真实地址。设置文案直接说明 API 中转站理论上能看到发给角色的聊天内容，举例展示「具体地址 → 在家附近」。
3. 区域外且精度足够：设备直连 `https://api.bigdatacloud.net/data/reverse-geocode-client`，无密钥、无 Worker／代理、无 Cookie。请求使用当前设备坐标；不使用 IP 定位回退，也不拿预存的隐私圈中心点查询。
4. 免费服务只将国家、省市、区镇等描述字段交给提示词，不传经纬度、邮编、Plus Code 或完整响应。免费服务返回的是区域，不保证识别具体建筑、商场门店或楼层。

高德模式同样先匹配本机隐藏地点，圈内不会加载查询 iframe。圈外通过其 `/v3/geocode/regeo` 的 callback（JSONP）接口直接查询，不经过 Worker／代理、不加载完整地图 SDK。查询脚本在只有 `allow-scripts`、没有 `allow-same-origin` 的 iframe 中运行，不能读取父页面的 localStorage、隐藏中心点或聊天；内层 CSP 仅允许查询高德，禁止 connect/img/form。消息回程同时校验 frame.contentWindow 和本次随机 token，成功、失败或取消后清除 frame 与监听器。

手机 WGS84 坐标只在本机近似转换为高德 GCJ02 坐标，隐藏距离判断仍使用转换前的 WGS84。转换算法改编自 MIT 的 [coordtransform](https://github.com/wandergis/coordtransform)，授权声明保留在 `amapCoordinates.ts`。返回只读取 formatted_address／地址文字与 100 米内最近 POI 名称，不读取电话、经纬度、ID；位置仅作参考，具体以 user 的说明为准。Key 仅存在本机并直接提交高德，不进入角色提示词、共享配置或备份。高德查不到／Key 无效／网络阻断时位置未知，不自动切换免费服务。

BigDataCloud 会收到区域外坐标及请求 IP，并将它们用于改进其 IP 定位数据。设置里明确展示这个用途及说明链接：[服务说明](https://www.bigdatacloud.com/docs/article/why-is-reverse-geocoding-api-free)、[客户端接口](https://www.bigdatacloud.com/free-api/free-reverse-geocode-to-city-api)、[使用政策](https://www.bigdatacloud.com/docs/article/fair-use-policy-for-free-client-side-reverse-geocoding-api)。仅设备直接请求当前授权取得的位置；不在服务端调用、不自动兜底其它地图接口。

隐私配置单独保存在 `os_user_location_privacy_v1`，不进入 RealtimeConfig、角色卡、整机／云端备份或 localStorage 镜像；导入备份保留本机已有定位设置，新设备导入后仍默认关闭，需重新设置隐藏地点与 Key。当前设备坐标不落库，区域外地点查询短缓存只在内存中保留最多五分钟，且每次复用前必须取得新定位并再次判断隐私圈；距旧查询位置超过 50 米则重新查询。定位请求本身并发合并，不做后台轮询或轨迹记录。

Umami 只在 `当前功能启用` 冷启动快照中报告「真实定位」开关（开／关／读取失败），不收位置、隐藏地点、半径或 Key，不在定位或保存时逐次打点。本地开发照常不发送统计。

地点查询 URL 含坐标，OSContext 的 fetch 拦截器对这个固定地址直接透传原 fetch，避免落入 API 完整抓取、请求比较缓存及网络失败诊断。此功能不把服务商原始错误写入日志，界面与提示词只显示不带坐标的失败说明。浏览器自身开发者工具仍能查看本机发起的网络请求。

查询期间关闭开关、修改隐私区域或切后台会丢弃结果；已有地点请求可被中止，但已发出的网络数据无法撤回。新增隐私圈保护下一次查询。隐私配置损坏或不可读取时不定位、不查询。权限拒绝、精度不足或网络／CORS 失败时只标记位置未知，不复用旧位置，也不回退代理。

## 互动入口

独立一次性「真实定位来了」公告排在启动更新队列最前面，沿用解锁／数据就绪门禁。只有明确关闭、返回、知道了或去设置才记已读；去设置直接打开真实定位子页并退出本轮公告队列，不自动开启功能、不请求定位。公告不发送新的统计事件。

- 私聊与 3D 小屋对话：在本次请求的实时尾段加入经过处理的位置，本地有天气时位置紧随天气、在热点前，只注入一次；云端即时对话保留在本轮 Live Context 中，天气由 Worker 临时补齐。模型／用户配置的模型中转会看到这一段文字，隐私圈内只看到别名附近，不看到半径。
- 通话与见面：通过 ContextBuilder 显式 `includeUserLocation` 加入本轮设备信息；见面关闭线下时间感知时按架空场景处理，不注入。
- 后台主动消息 fire-pack 不读取位置、不把历史定位快照同步上云；开启真实定位时模板只带「xx现在的定位未知」及相同参考说明，关闭或配置不可读取时不带位置段。定时生成使用这份模板，即使刚刚前台定位过也不复用它；即时对话仍保留发送当轮的位置。剧情剧场、日记／记忆整理等生成器不读取位置。关闭定位不会删除模型此前已回复或记住的地点文字。

提示词只提供位置参考，并说明以 user 自己的说明为准，不追加「不推断、不追问」等行为限制。定位本身不切换见面模式。

位置块标题与正文使用真实 user 名称，例如：

```text
### 小雨当前的位置
小雨现在的定位在家附近，作为辅助参考背景信息，具体以小雨的说明为准。
```

范围外将「家附近」替换为已过滤的地点文字。边界不确定时写「定位可能在…」，失败时只写「定位未知」。设备权限、超时、高德 Key 类型不匹配等失败说明只显示在预览界面，不写进角色提示词。

## 验证

`utils/userLocation.test.ts` 验证两种服务圈内零网络、边界误差保护、默认关闭、后台禁止、无 IP 回退、原始字段不进提示词、配置损坏、缓存与并发修改；`userLocationContext.test.ts` 对照真实载荷的本地／即时对话、天气旁单次注入、通话／见面共用管线及 fire-pack；`userLocationSettings.test.ts` 验证本机添加、保存后预览和直白示例。`amapUserLocation.test.ts` 验证坐标转换、字段过滤、隔离查询、伪造回程拒绝、取消与清理。所有坐标及服务响应为模拟数据，不定位开发者或用户。

`test/fixtures/user-location.html` 是独立 5192 端口的实际设置组件 + 模拟设备与地图服务验收页。真实设备定位精度、国内网络连通性和各平台权限行为仍需在目标设备验收。
