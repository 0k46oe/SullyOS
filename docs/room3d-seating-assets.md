## 矮垫坐姿（2026-09-29）

用户指出矮垫应接近柔和的坐地动作，随后明确简化为**双腿自然朝前、脚平放，不侧收腿**。客厅 `bedroom_ref_flower_pouf` 已接二号专属 `floor` 坐姿；原版 Chibi 与普通沙发保留原坐位。

核对的一手参考：

- [ZEPETO 官方家具交互教程](https://docs.zepeto.me/world-sdk-guide/interacting-with-an-object)：家具配置 AnimationClip 与 DockPoint，坐姿将 Hips 对齐目标；播放后的骨骼位置参与根节点校准。官方示例入口为 [naverz/zepeto-world-sample Chapter3](https://github.com/naverz/zepeto-world-sample/tree/main/Assets/Chapter3)。可借鉴动作选择与座位接触分离，不能据此声称其会自动生成所有高度的坐姿。
- [VRChat Station](https://creators.vrchat.com/worlds/components/vrc_station/)：支持为坐位覆盖自定义动画控制器，并分别指定进入与退出位置。可借鉴按家具指定动作类型。
- [VRoid 姿势工具](https://vroid.pixiv.help/hc/ja/articles/21044295117721)：移动腹部时联动调整膝部，手脚与关节控制器可分别细调。可借鉴骨盆下降时配合脚底接触，文档不等于现成的运行时入座算法。
- [YUI 动作目录](https://yw0nam.github.io/YUI/reference/motions)：明确列出单侧折腿、侧坐、抱膝等 floor sit，以及并膝垂腿的 edge sit；坐下/起身与坐定循环独立，记录髋部下降/上升曲线。这是项目公开文档所描述的行为，本轮未导入或实际播放其素材，素材授权需独立核对。

实现：`seating.js` 用经实坐确认的资产 ID 指定姿势，只为花形坐垫增加二号向前 0.20 的局部坐位偏移，随家具旋转；不按名称或高度猜类别。坐下/起身各 2.2 秒，坐定保留并膝向前放腿、平鞋底和轻微呼吸；按用户补充，双手自然垂在身体两侧，不搭在腿前。挥手只叠加上身，结束后回到两侧垂手。房间比例按用户最新确认暂定 200%（此前为 172%），骨长比例保持不变。

`floorSeatContact.ts` 复用 Three.js 自带 `CCDIKSolver` 做脚底及过渡支撑手接触，腿的前伸距离由真实骨长和座高决定。虚拟目标只提供给求解器，不增加蒙皮骨骼；现有 48 骨、衣物绑定不变。`visitor.seatScale` 明确提供身体内部缩放，避免用外层空容器的 scale=1 错换单位。此处为该坐垫的动作适配，不是通用衣物/家具碰撞求解。

验证：三档身高的脚踝接触、膝间距、挥手保持坐姿、骨长及骨骼数不变，坐下/起身阶段和旋转坐位等共 25 项相关测试通过；客厅对照页生产构建通过，实际前/侧视角和过渡截图位于 `.tmp/floor-*.png`。参考项目仅借鉴交互结构，没有导入新动作资产。近座过渡仍从座位前的安全落点开始，远处走近并转身入座尚未接入。

## 二号素体客厅动作第一组（2026-09-29）

二号与原版共用家具动作含义，但姿势由自己的骨架表达。`blankMotion.ts` 的客厅动作是本项目编写的 FK 姿势与阶段曲线，没有新增外部动作素材；此前选中的五段试衣动作与来源记录不变。

用户补充：小人也需要三渲二。后续动作视觉验收需遵守 [小人渲染方向](chibi-clothing-assets.md#小人渲染方向用户确认2026-09-29)，在统一材质与光照下复核轮廓、五官可读性及衣物接触。

- 坐下/起身使用 `seatChange.js`：在座位前方查找真实可站立落点，1.05 秒内屈膝、微前倾并移动到坐垫接触点，起身反向进行。坐姿收窄两膝，减少晃脚。这里只补近座过渡，尚未加入从房间远处走到沙发再转身的完整入座流程；找不到安全落点或系统减少动态效果时保留原有直接坐姿。
- 行走使用二号自己的屈膝、脚踝与低幅摆臂，移动速度 1.05 房间单位/秒。浇水分为抬壶、倾倒、收壶，手指微握；壶把跟随实际右手，两腕靠拢托住小壶，出水仅在倾倒阶段出现。原版的壶位与步速保留。
- `visitor.navigation` 按当前身高提供头部垂直区间；寻路与浇水保留躯干占地，避免将原版圆团的低头部区间套在二号腰部。二号浇水可检测盆栽四侧的斜向落点，仍拒绝被家具挡住的点。客厅龟背竹可用，墙角枝叶树仍可能因真实空间不足不可用。
- 头顶按实际素体、头发包围盒加少量余量测量。默认小栗头顶约 2.45，旧门洞净高 2.35；当前会拒绝穿过该低门洞，房内行走可用。低头屈膝过门留作下一组动作，不通过缩小角色或忽略门楣碰撞绕开。
- 切换动作、换人、布置及换房取消临时过渡并恢复可用姿势；近景相机不再中断坐姿过渡，坐姿/浇水近景略俯视以避免茶几挡住角色。

实现前核对了 [Three.js CCDIKSolver](https://threejs.org/docs/pages/CCDIKSolver.html) 与 [Unity Two Bone IK 的目标/肘部提示机制](https://docs.unity3d.com/ja/Packages/com.unity.animation.rigging%401.2/manual/constraints/TwoBoneIKConstraint.html)。本组固定小壶使用已校准的 FK 与手部挂点；后续键鼠、灶台等不同高度的家具接触仍需专门适配，不宣称已有通用 IK 或布料碰撞。

验证：`chibiRoomMotion.test.ts` 覆盖三档身高骨长不变、骨骼矩阵有效、动作中断回站姿、旋转座位端点、头/躯干/高处障碍及水壶阶段；联合家具交互、浇水、坐位、双体型检查共 22 项通过。对照页生产构建通过。

2026-09-18 新体型试版：Tiny T-Pose 使用真实骨骼屈髋/屈膝，`blankMotion.ts` 在身体局部归一化坐垫接触高度，继续复用 `seatOffset=0`；站着/坐着挥手共用上身动作，坐姿不跳跃。坐下默认双臂自然垂在胯部两侧，袖子留少量外侧空间；挥手只抬起一侧，点「坐好」后恢复两侧垂手。下文四颗手脚球规则属于原版圆团体型，新体型不追加球、不伸长四肢。新体型的设备接触与其他座椅仍需逐项校准。

此规程适用于今后导入的所有椅子、沙发、坐墩等座类家具，无论收到 GLB、FBX、OBJ、BLEND 或其他格式。先评估和修改，再进入家具架。花瓣沙发是首个验收样例，已有旧座椅须逐件补验，不能仅凭类别自动开放坐下。

## 1. 检查与统一

- 记录原文件的尺寸、顶点/三角形数量、材质数、纹理数量与尺寸、文件体积。输入保留在制作区，原始大文件和 AI 图片不直接进入 `public`。
- 最终交付自包含 GLB，+Y 向上、+Z 朝座椅正前方，底部 y=0，水平包围盒中心 x=z=0；清理隐藏物件、相机、灯光、未用材质和贴图。
- 对照 chibi 与阅读茶几调整尺寸，不以来源文件的单位直接摆放。目录 `size`、碰撞 `boxes` 和坐位坐标均使用最终归一化尺寸；加载器按 `size[0]` 统一缩放。

## 2. 材质与模型

- 不使用 AI 生成的图片贴图，也不将其烘焙成新图或逐点颜色来规避限制。按几何部件手工划分纯色材质，颜色由项目配色与人工选择确定。
- 浅原木沿用 `kit.glb` 的 `woodLight`（阅读茶几台面），保留其线性颜色值。布料、木框、装饰分别上色；用户换色只作用于指定布料，木头与装饰不被整件染色。
- 优先低面数来源，去除不可见内部重复面、修补破面并平滑法线；保留轮廓和必要硬边。不要用增加细分来遮掩错误法线。
- 普通小座椅以约 5,000 三角形、8 个以内材质/绘制提交、200 KB 内无图 GLB 为目标。超出时先检查原因、简化并记录实际代价；这些是预算目标，不以破坏轮廓强行达标。加宽花瓣双人款为 4,858 三角形 / 97,288 字节，单人款为 3,624 三角形 / 74,476 字节，均为 6 材质。
- 同款实例共享几何与材质模板；无额外渲染器、无逐帧模型重建、静止时遵守小屋省电停绘。目录外部 `url` 条目在重新导出 kit 时必须保留。

## 3. 校准坐位

`catalog.json` 的 `seats` 只加入已通过实坐检查的位置：

```json
"seats": [{"id":"center","label":"中间","position":[0,0.63,0.55],"rotation":0}]
```

`position` 是坐垫支撑面的接触点，相对家具底部原点；`rotation` 是绕 +Y 的角度（度），0 朝 +Z。运行时跟随家具旋转和平移，再减去小人自己的 `seatOffset` 放置模型根节点。该偏移按坐姿的实际下表面校准，不能拿髋部旋转中心的高度来代替，否则小脚会埋进坐垫。不要在每件家具里重复硬编码身体比例。

- 座位数量按头部和发型包围范围确定，不按坐垫数量或模型名称推断。花瓣双人款宽 3.70，坐位 x=-0.94 / +0.94（间距 1.88）；单人款宽 1.92，坐位 x=0。两款保持相同座高和深度。已用两只同体型 chibi 同屏验收，实际多人行为接入仍需占位检查，尤其是宽大马尾或头饰。
- 正面、侧面、背面检查接触面、小脚朝前、手不伸长、头发/头部不嵌进靠背或扶手。至少检查普通发型及外伸发髻/马尾；不能靠缩小角色蒙混适配。
- 当前手动「小人 → 找个位置坐坐」直接放入坐位，挥手、生气、晃动和打瞌睡叠加在坐姿上，点「坐好」只结束表情动作，点「站起来」才返回地面；收纳/移除座椅或离开房间释放坐位。坐姿属于临时动作，不写入角色外观或家具存档。
- 自主寻路、走近转身坐下、多人占位尚未实现；添加这些功能时复用坐位元数据，不按家具名称猜位置。

动作手脚采用四个独立圆球（`chibi-action-hand-*` / `chibi-action-foot-*`）：手球在坐姿、挥手、生气、晃动、浇水和设备互动时显示，原手片隐藏；脚球仅在坐姿显示，站着的任何动作都不显示脚球；普通站立/行走恢复原手脚外观。共用一个平滑球体几何，小手取角色肤色，小脚取已有 chibi 服装底部颜色，无新图片。坐姿脚球在局部 z=0.68、y≈-0.10，轻微晃动；身体接触面和 `seatOffset=0` 不变。仅收回原素体 y≤0.105 的脚尖突出部分，下半身不拉伸、不弯成底座。

动作接口为 `animate(time, motion, posture)`，`posture` 独立表示 `standing` / `seated`；坐位决定姿势，动作按钮不清空坐位。坐姿中的可爱挥手保留 `><` 和歪头，关闭全身蹦跳；睡眠为闭眼点头，关闭侧躺；生气/晃动保留头部和小手动作，关闭跺脚与整身旋转。身体根节点保持接触坐垫，小脚球独立垂在前面；手球只移动、不缩放。球体转动看不出挥手，因此其中心沿小幅弧线左右移动。原 `sit` 动作值仅保留兼容，房间正常使用坐姿 + `idle`。

两款优化模型可用 `pnpm node art/jellyfish-home/petal-variants.mjs` 从 `art/jellyfish-home/sources/petal-sofa-solid.glb`（已去图纯色源）重建。只加宽双人座面/靠背，扶手、木脚和装饰保持原尺寸；单人款合为一块坐垫，装饰按单人空间重新排布。修改双人宽度时需同步碰撞盒与坐位；旧存档只有发生碰撞/越界的该款实例才重新找位置，无空地时收纳，保留实例 ID 和布料颜色。
