# 美化分享码

提供私有投稿、人工审核和凭码领取，不提供公开作品列表、搜索、评论或关注。

## 入口和使用流程

- 外观装扮提供「内置桌面主题 → SULLY」，包含桌面壁纸、小组件和 32 个图标（含彼方、热点）。素材独立按需加载；应用前全部转为可持久化内容，沿用本机 Blob 存储，因此已应用素材随整机备份和保存的预设搬家。只覆盖桌面样式，不导入原主题包夹带的聊天气泡或改动现有聊天设置。原壁纸 1270×2458 PNG 压为 1080×2090 WebP、质量 72，约 176 KiB；全部素材约 727 KiB。

- 浏览按归属分开：ChatApp「聊天装扮」只收白框、气泡、头像框、聊天背景、心象、提示音；外观 App「外观装扮」只收桌面主题、日程表、交换日记。不会移动或删除既有本机文件，只过滤所属入口。
- **作者界面始终统一**：两边的「分享装扮」进入同一个文件／图片／码分享流程，选择预设时能查看所有分类；同一作者身份、我的提交、审核状态和一键更新不受入口分类限制。
- 「导入装扮 → 用码领取」仍接受全部分类，不要求用户换入口。接收后按作品内容归入对应库；聊天美化选择角色应用，桌面主题应用到桌面，日程表／交换日记样式全局应用。日程表样式同步桌面组件、聊天日程和其他既有日程卡使用处。
- 日程表／交换日记拥有独立制作器、内置主题和「保存当前样式」。现有 App 样式设置提供跳转入口。App 预设复用 `sullyos-chat-decoration` 传输包的 `schedule` / `journal` 部分（`kind` 仍是 `chat-decoration`），用户界面按实际分类展示；每份只包含一个 App 样式，不混入聊天装扮。验证器只保留样式字段，拒绝越界 CSS，不导出真实日程、日记或角色资料。
- 日程预览复用真实卡片组件的展示层，时钟和日程使用固定示例；日记预览使用示例日记本和现有主题样式。二者在隔离的预览容器中渲染，不读取真实内容。聊天「我的搭配」只组合聊天部件。
- 装扮页采用独立标题栏与横向分类；只有聊天入口提供角色选择和「我的搭配」。分类取自结构化内容，可重叠；任意聊天 CSS 只归白框，不猜测其中组件、不自动拆分。详情列出会应用的部分，按完整作品应用。

- 首页「我的装扮」只展示本机已保存／已导入的预设，不请求云端作品目录。各类装扮按三列缩略图展示，每页 12 款，右上角搜索可按本机名称筛选。预览进入可视区域才读取，数据版本不变时普通页面刷新不重复导出；点缩略图打开独立大图详情，底部立即应用桌面主题或选择聊天角色。作者规范来自领取时保存在本机的来源记录，无来源的文件标为本机预设。
- 用码领取页只负责领取。分享装扮分为文件分享、图片分享、码分享；文件和图片从本机预设弹窗选择，图片沿用可导入的 PNG 分享卡，码分享包含投稿和我的提交，仅显示当前作者自己的作品。领取说明页可按需下载已审核版本预览，确认作者规范后才导入；真正领取时再次校验下载状态，撤销的分享不会因已有预览而继续导入。
- 选中预设即可预览，不需要先登录。默认/动森桌面预览静态复用真实 Launcher、图标、角色卡和组件，按预设排序与组件设置展示全部分页，可用页码选择及前后按钮切换。静态渲染不挂载副作用，不读取角色或真实聊天、不应用到本机；角色、消息与音乐使用独立示例状态。其他特殊桌面皮肤仍使用示意模板。CSS 在独立 Shadow DOM 内展示，宿主强制尺寸和绘制隔离，不插入脚本；实际屏幕比例、私人内容和特殊皮肤可能有差异。
- 投稿分为「确认作品 → 署名与规范」两步。预览成功后点击「就是这份，继续」，固定当前已预览包的快照；下一步再登录、填写说明并送交审核，不重新读取可能发生变化的本机预设。重新选择会取消确认；读取失败不能继续，上传失败保留已确认作品和说明供重试。新投稿与更新采用同一确认流程。
- 已发布作品可在「我的提交 → 分享预览图」生成带预览、美化名、署名、使用权限和分享码的 PNG。使用当前已审核版本，更新待审期间仍展示旧版；图片不嵌入预设文件，只引导凭码领取。图片在设备上生成，不上传新的图片到 R2。复杂 CSS 与跨域图片可能受浏览器导出能力限制。
- 「导出分享码」选择当前聊天装扮、保存的预设或上传导出的 JSON / ZIP / PNG 分享原图。外观先保存当前设置为预设再选择。
- 首次投稿设置密码，服务生成作者码。当前浏览器保存会话；更换浏览器用作者码 + 密码恢复。作者码和公开分享码是不同凭据；服务器只保存密码派生值，不保存明文密码。
- 说明含美化名、署名、发放平台（可多选）、联系说明、二改/二次传播许可、当前导出应用版本、Bug 反馈偏好和作者留言。平台用于告诉使用者去哪里找作者 Repo；本服务不会向 QQ 或 DC 发消息。
- 提交后在「我的提交」刷新状态，待审显示「人工审核中」，并提示通常需要 1–2 天；新投稿与更新投稿口径一致。通过后生成稳定的 `S-…` 分享码；退回显示管理员说明。没有自动推送通知。
- 更新必须重新审核。在审核和退回期间，分享码继续指向上一份已通过文件。重复/过期更新返回冲突，用户刷新后重试。
- 作者可立即删除；分享码和所有私有下载接口马上失效。已下载的副本无法收回。
- 领取先查看作者规范并确认。外观通道领取后先存入对应本地预设列表，再询问「是否立即应用」：外观预设应用后返回桌面；聊天装扮确认当前角色或主动勾选全部角色后应用，留在装扮库。可选择暂不应用，之后从预设列表使用。聊天与外观入口共用领取与应用确认流程。

### 统一导入、署名与个人搬家

- 「导入装扮」合并分享码、直接 CSS、文件／图片三个入口。文件和相册使用独立选择按钮，分享码仍统一识别桌面主题与聊天装扮。旧 CSS（含 CSS/TXT 文件及旧分享图中的纯 CSS）未识别署名时，导入前必须明确选择自制或外部导入，不能默认冒认为自制。
- 分享页提供带署名的 CSS 复制；CSS 头部 `SULLY-BEAUTY-V1` 记录名称、署名、分类与二改／传播规范。JSON、ZIP 与可导入 PNG 同样携带 `beautyOrigin`。重新导入按外部来源处理并保留限制。署名是可读的来源标记，不是防伪签名；原有作者署名不能由分享页新填的署名覆盖。CSS 复制仅包含样式，完整素材和布局仍用文件／图片分享。
- 「我的搭配」以大预览为主体，窄屏从右侧展开选择，宽屏并列显示；「保存当前搭配」生成新的本机搭配，保留组合来源限制，不自动应用。搭配在原资产存储中标记 `_collection: outfit`，仅显示在「我的搭配 → 收藏」，不进入聊天装扮列表或单件选择器；统一作者页仍可分享搭配。编辑和整机备份保留标记，公开预设文件不携带该本地标记。旧数据没有标记时保留原归类，不通过名称猜测迁移。制作器依旧只处理各自分类。
- 作者可主动开启「记住作者身份，随个人完整备份搬家」。现有登录用户需再次验证密码，才会将作者码和密码存入本机 `sully-beauty-author-identity-v1`；退出登录或关闭记住身份会移除此记录。服务器仍只保留密码派生值。
- 该身份仅进入个人完整备份的 `beautyAuthorLocal`，不进入文字／媒体分包、装扮预设、CSS、PNG 或分享码投稿。导入恢复后填入作者登录表单，由用户点击登录；不自动上传、不迁移旧会话令牌。服务地址不匹配或字段无效时拒绝恢复身份，旧备份缺少该字段时不清除已有身份。
- 完整备份携带本地装扮实际内容、稳定 ID、来源及投稿绑定，不依赖分享码重新下载。分享码用于后续检查更新；作者改稿、撤回或服务离线不会改变备份中的历史内容。

### 原件关联、更新与收藏操作

- 本机聊天预设保存 `_libraryId`，改名、编辑原件和排序均保留 ID；另存副本生成新 ID。旧数据首次读取时迁移，不按同名作品合并。这个字段仅在本机数据库与整机备份中使用，导出和投稿经 `validateDecoration` 去掉。桌面主题与独立气泡沿用已有 ID。
- 投稿成功才把作者码 + 投稿 ID 关联至本机源 ID、规范化内容 SHA-256 和最后提交 revision（`beauty_binding_*`）。绑定的是已确认并实际上传的快照。我的提交「一键更新」读取原件、比较摘要，未修改不上传；修改后用应用内弹窗确认，再调用现有更新接口并携带 `expectedRevision`。待审时不能再次更新，通过后才替换已发布版本。
- 直接上传设备文件、旧投稿、删除了源预设或换设备未恢复整机备份时，没有可可靠定位的本机原件。使用「选择文件更新」选择已保存预设并投稿成功后建立关联；不按名字或列表位置猜测。作者登录仅恢复云端身份，不会恢复本机文件关联。
- 码导入原件提供「检查更新」，仅请求该码当前已审核版本。不同版本先显示作者规范并确认，再下载校验和替换本机收藏；待审版本不可下载。保存文件与来源版本同事务提交，失败保留旧文件和旧版本；更新不自动应用到角色。允许二改的副本保留原作者规范，但不再跟随原分享码更新。
- 收藏卡标明自制、二改、文件导入或码导入；历史来源确实未知的保持「旧版预设」，不冒认自制。禁止二改的原件锁定编辑。卡片「分享」仅自制显示，进入分享页并选中当前作品；码分享默认打开「投稿获取分享码」。删除为红色操作，应用内弹窗确认，只移除本机收藏，不撤销云端发布。独立气泡被删除后，使用它的角色回退默认气泡，弹窗对此说明。

## 服务和数据

### 私密 Repo 与本机邀请

- 有分享码作者来源的本机作品在缩略图和详情右上角显示轻量「待 Repo」入口，导入后即可打开，不要求先应用或使用满三天。可以写私密反馈，也可以勾选「我已当面完成 Repo」；后者只保存在本机 `sully-beauty-repo-status-v1`，可撤销，不向后台或作者发送通知。提交私密反馈成功后标为「已写 Repo」，并不表示已人工转达。两种完成状态均停止该分享码的后续使用提醒，重复导入和换版本不会重置状态。普通无作者来源的文件不猜测署名或 Repo 状态。不展示完成比例、数量或红点，不影响领取和应用。

- 分享码来源保存在本机 `beauty_source_*` 资产中，外观绑定导入后的预设 ID，聊天装扮绑定规范化包的 SHA-256；不向美化包附加账号、聊天或使用记录。只有应用成功后才开始记录，领取但未应用不计时。
- 首版按应用后经过 **72 小时以上**计算，不累计屏幕点亮时长。记录存在 `sully-beauty-usage-v1`；切换主题、重置或手动改动对应外观字段会停止该轮计时。再次应用可重新开始。角色资料、消息内容不参与统计。
- 邀请只在解锁后的桌面空闲时出现，避开已有公告、备份和对话框；同一分享码仅主动提醒一次，全局每天最多一份。可关闭提醒，在「外观 → 外观装扮 → 给美化作者写 Repo」手动打开当前使用作品的表单。历史版本已应用但没有记录来源的预设不会补算时间。
- 用户可以自行按作者填写的平台和联系说明寻找作者，或提交署名及最多 1200 字反馈。同意人工转达前不能提交。首版不收图片、聊天、角色名或联系方式；署名为用户自行填写，不作真实身份认证。
- `POST /api/repos` 校验曾审核通过的作品版本、格式和明确同意。每 IP 每天 5 次、每本机随机标识每天 3 次、全站每天 1000 次；请求幂等键由 pepper、本机随机标识和请求 ID 派生，不存原始设备标识。限流与幂等标识用于防重复，不是硬件设备认证。
- `beauty_repos`（迁移 `0002_private_repos.sql`）只允许管理员查询和更新状态。没有公共 Repo 列表，也没有作者直接读取接口。作品后续更新不会改变旧 Repo 对应的作者说明快照。
- 后台「私密 Repo」可按状态、作品名、美化码和作者码筛选，每页 12 份；可预览并导出单份 PNG，或勾选同一作者最多 3 份生成合集卡。图片在管理员浏览器生成，不外发、不额外存入 R2。管理员手动用 QQ 发给作者后，再标记「已转达」；可归档或恢复待转达。导出不会自动改变状态。
- 普通用户的「我的提交」和管理员作品队列也统一为每页 12 份，显示总数、上一页／下一页。处理最后一页的最后一项时自动回到有效页；按更新时间和 ID 稳定排序。

- Worker：`worker/beauty-share/src/index.ts`，服务 `sullyos-beauty-share`。
- D1：`sullyos-beauty-share`，维护作者、会话、投稿版本、审核指针及额度；迁移位于 `worker/beauty-share/migrations`。
- R2：`sullyos-beauty-share-private`，不得打开公开访问或绑定公开存储域名。所有下载经 Worker 校验已审核指针或作者/管理员身份。
- 正式服务域名：`https://beauty.friedsully.com`；管理界面：`https://beauty.friedsully.com/admin/`。域名已在 Cloudflare Dashboard 绑定，也记录于 Wrangler routes。地址不是安全边界，所有管理员 API 独立鉴权。页面只渲染文本，不注入投稿 CSS/HTML，也不自动加载投稿里的素材地址。
- 客户端默认服务地址在 `utils/beautyShareClient.ts`，自部署可用构建环境变量 `VITE_BEAUTY_SHARE_URL` 覆盖。不能在前端配置中放管理员密码、Cloudflare Token 或 Worker secrets。
- 作者会话在本地 `sully-beauty-author-session-v1`，常用说明在 `sully-beauty-author-defaults-v1`。这些不写入预设包。作者会话 30 天，管理员会话 8 小时；服务端仅保存会话 token 的 SHA-256。
- 密码用 PBKDF2-SHA256、独立随机盐和服务端 pepper。不要无意轮换 `AUTH_PEPPER`，否则已有密码无法验证。忘记作者密码暂不提供自助重置；管理员也看不到原密码。

不进行服务端 AI 内容审核。服务仅做格式、大小、权限和频率约束。人工审核下载规范化的 JSON；是否通过由管理员决定。

## 首次部署

1. 创建私有 R2 桶和 D1 数据库，修改 `wrangler.jsonc` 里的账号与资源绑定。
2. `pnpm dlx wrangler d1 migrations apply sullyos-beauty-share --remote --config worker/beauty-share/wrangler.jsonc`。
3. `pnpm dlx wrangler deploy --config worker/beauty-share/wrangler.jsonc`。全新部署首次需将 `UPLOADS_ENABLED` 设为 `false`；当前账号已初始化管理员并开放投稿。配置含自定义域名，CLI 后续管理路由需对应 zone / routes 权限。
4. 通过 Wrangler secret 设置 `AUTH_PEPPER`（随机至少 32 字符）与 `BOOTSTRAP_HASH`（随机一次性初始化 token 的 SHA-256）。密钥文件使用被 Git 忽略的 `.dev.vars.*`，不得提交。
5. 本人访问 `/admin/#setup=<初始化token>` 设置账号和密码。页面立即移除 URL fragment；D1 唯一索引保证仅一个管理员。已有管理员后初始化接口拒绝再次建立。
6. 初始化完成后删除 `BOOTSTRAP_HASH` secret；将 `UPLOADS_ENABLED` 改为 `true` 并重新部署。发布应用客户端是单独步骤。

## 额度和清理

默认单文件 20 MiB、每作者最多 50 份活跃作品、每小时 6 次上传、每 IP 每天 3 次注册。全站每天接受上传 256 MiB，总保留文件计数上限 8 GiB，可在 Worker vars 调整。失败请求也可能消耗频率和当天上传额度，防止反复失败绕过限制。

这些是业务限制，不是 Cloudflare 账单封顶。Worker 请求与 D1/R2 操作仍计入各自用量。公开下载不经过公开桶，不缓存可撤销的包；需要关注下载量和调用量。投稿入口可用 `UPLOADS_ENABLED=false` 暂停，已通过作品仍可领取。

数据库事务维护版本和分享指针。下载附带 revision，作者发布新版后，旧详情发起的下载返回 409，需重新查看规范。删除先撤销数据库可见性，再清理文件；清理失败由每日 Cron 重试。过期会话、频率窗口和被替换的历史文件同样由 Cron 清理。

R2 与 D1 没有跨服务事务。一般写入失败会立即清理对象并归还容量，但 Worker 在对象写入后被强制终止，可能留下没有版本记录的对象和占用计数。出现容量与版本统计不一致时，维护人员应对照 `revisions.blob_key` 核对桶，确认孤立对象后再清理；不可盲目重置 `limits` 中的 `storage`。这不会让未审核内容公开。
