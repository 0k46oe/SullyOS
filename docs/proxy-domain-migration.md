# 主代理自有域名迁移

主代理 Worker `sully-n` 新增自定义域名 `proxy.friedsully.com`，与旧域名 `sullymeow.ccwu.cc` 指向同一份生产代码。保留旧绑定，不对 API 请求做跨域重定向，不修改 Worker 密钥、绑定或业务代码。两个域名的 `/api/health` 均已返回 HTTP 200 与相同健康信息。

新域名携带 Origin、POST 和 content-type/authorization 的 OPTIONS 预检实测返回 204，允许来源、方法和请求头均正确。该验证不代表所有地区网络或所有上游业务均已测试。

前端默认地址由 `utils/proxyWorker.ts` 统一定义。更新应用后，历史公共主机名按 URL hostname 精确识别，避免误改自建域名或路径里恰好含旧字符串的地址：

- 中心代理本地配置：读到旧公共主机名就跟随新默认。
- 音乐独立配置：旧公共主机名收敛为空值，继续跟随中心代理；真正的自建音乐地址保留。
- 小红书等单独保存完整 URL 的配置：沿用 `rewriteStaleWorkerUrl`，保留路径与查询参数。
- 新生成的主动消息 Worker 包：默认地址与运行时注入的旧公共地址一起迁移。已部署旧 Worker 仍可使用旧域名，须更新用户 Worker 才能获得新的内置迁移逻辑。

README、调用说明和网络诊断示例同步新入口。旧域名只在迁移说明、历史匹配和迁移测试中保留。不要把 `friedsully.com` 下已有的美化、素材库和统计服务一并替换。

这不是前端站点迁移：不更换用户访问网站的 origin，不清理 IndexedDB、localStorage 或推送订阅。自有域名便于管理与更换，但不能保证所有地区网络都始终可达。

上线应用代码前，确认新域名 HTTPS、健康响应及 CORS 预检可用；旧绑定继续保留供旧网页、旧 APK 和用户 Worker 过渡。需要回滚时恢复中心默认值和迁移名单，不删除用户自建配置。
