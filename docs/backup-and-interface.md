# 聊天查找配色与本地备份

## 聊天查找配色

聊天工具 → 查找聊天记录，标题右侧可切换 Claude 色系日间／夜间。选择仅用于查找页，并在本机记住，不跟随聊天美化、全局主题或系统日夜模式。

采用 Anthropic 品牌基础色 `#faf9f5`、`#141413`、`#e8e6dc`、`#b0aea5`、`#d97757`，中间层及日间强调色按可读性调整。查找页通过 Shadow DOM 隔离样式，包含独立的输入框、日期日历、结果、关键词高亮和分页配色。

本轮新增的全局 Claude／黑白简约风格、外观设置入口及默认聊天换色已撤回。旧备份中残留的 `interfaceStyle` / `interfaceColorMode` 字段不再参与渲染。其他原有美化、工具区和排序功能不变。

## 文字与美化分开恢复

文字备份恢复人物设定、用户资料、消息、记忆和设置；美化备份恢复主题、图标、素材库、头像、背景和可对应的消息图片。文字中的空图片占位不再表示删除已有图片，美化中的旧姓名、提示词、日期和正文不覆盖当前文字。

文字 → 美化、美化 → 文字都支持。冷恢复时，角色和好友圈等尚未存在的媒体映射先保存在本机，后续文字导入按稳定 ID 补回；完整备份恢复后清除这批旧映射。数组以记录 ID 匹配，避免重排后配错图。完整备份仍使用原有整表替换/合并规则。导入文字备份中的聊天历史会替换该快照范围，不能当作追加聊天工具。

「导入 / 组合恢复备份」支持同时选择一份文字和一份美化备份，校验后按文字、美化顺序恢复，最后统一刷新。同一批不要混选多个完整备份或两份文字备份。第三方系统备份仍不支持。

## 手机分卷导出

设置 → 备份与恢复默认勾选「分卷导出」。导出时逐批读数据库、逐片序列化、压缩并暂存到独立的临时 IndexedDB，完成后显示待保存列表：

1. 保存一个 `.sullyindex.json` 索引文件。
2. 逐个保存该组全部 `.sullypart` 分卷，每卷最多 16 MiB。
3. 恢复时在文件选择器中同时选中索引和所有对应分卷。组合恢复则选中两组的所有文件。

分卷是同一个 ZIP 的有序字节段，不能单独解压，也不能只恢复一部分。索引保存顺序、大小和 SHA-256；文件选择顺序不限。缺卷、重名、重复引用、非对应分卷或校验失败会在主要数据写入前拒绝恢复。普通旧 ZIP / JSON 继续支持，取消分卷勾选可以导出单个 ZIP；云备份仍使用单个 ZIP。

临时分卷保存在本机，重新打开设置后可以继续保存。导出被系统打断时，未完成的缓存会明确标注，不能当作有效备份。确认索引和全部分卷已保存到「文件」后，可移除临时备份以释放占用。浏览器可能驱逐临时存储，所以缓存列表本身不算异地备份。分卷不加密，隐私边界与原备份相同。

## memory_links 与验证边界

`DB.streamStoreBatches` 在同一只读事务中每次最多取 1,000 条；压缩等待期间通过 IDB 事件续接事务，避免异步阶段 WebKit 事务失效，并保持该表一致快照。并发写入会等待该表读取结束。`memory_links` 每片最多 5,000 条，显示已处理条数，不删除关联，也不改原数据库精度。

ZIP 恢复按范围延迟读取，`memory_links` 先逐片校验，再逐片写入，不重新拼成整表对象。其他现有表及向量恢复仍沿原流程，不能据此承诺任意数据量都不会触及内存/存储限制。整个多表恢复不是单个原子事务；写入中的存储不足等异常仍可能留下部分恢复状态，应保留原备份重试。

已在桌面真实浏览器验证十万条记忆关联全量导出/恢复、20 MiB 图片跨卷、两种导入顺序及组合恢复，并覆盖缺卷、损坏、存储写入失败、并发写入快照和旧 ZIP 兼容测试。没有 iPhone 14 Pro Max / iOS 26 PWA 的现场测试结果，不能宣称该设备闪退已被实机证实消除。
