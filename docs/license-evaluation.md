# PolyForm 许可评估（未变更现行许可）

当前目标是保留现有边界：源码可见，二改须另获授权，不默认允许再分发、公共镜像或商业使用。当前 LICENSE 继续生效；本文只记录选型，不授予额外权限。

## Shield 不匹配这次目标

[PolyForm Shield 1.0.0](https://polyformproject.org/licenses/shield/1.0.0) 的主要限制是不得提供与许可人相关产品竞争的产品，而不是禁止一切商业用途。它明确授予符合用途限制的修改与分发权限。因此它不能等价替换现有的「未经授权不得二改／分发」。

## Strict 更接近，但并非等价

[PolyForm Strict 1.0.0](https://polyformproject.org/licenses/strict/1.0.0) 不授予修改、衍生创作或分发权限，并限制用途为非商业，允许许可人另行给予授权。可以采用原文作为基础软件许可，再以独立书面授权向符合条件的社区成员开放限定的二改自用。

然而 Strict 授予所有符合条款的非商业用途，且明确涵盖若干非商业机构，并非仅限个人学习或官方社区。原文没有项目目前这种全面禁止公共托管服务的独立条款；不能简单声称「免费公共托管一定被 Strict 禁止」。因此在坚持现有全部限制的前提下，暂不自动替换 LICENSE。

如果以后决定采用 Strict，需要明确接受其基础授权范围，逐项区分：软件使用与复制修改、官方服务器访问资格、项目品牌、原创素材及第三方独立许可。不能用社区规则收回标准许可已经授予的权利。旧版本既有许可与无权重新许可的第三方内容也不能追溯改掉。

## 不要改了标准文本还沿用 PolyForm 名称

[PolyForm 官方仓库](https://github.com/polyformproject/polyform-licenses) 要求修改许可文本后移除 PolyForm 及官网标识。若为了完全保留现有限制而把额外禁止条件塞进 Strict，它就不能继续被当作未经修改的 PolyForm Strict。标准化的价值来自明确、可识别的原文，不只是名称。

结论：Shield 排除；Strict＋单独二改授权作为可选方案保留。若现有全部限制都不可放宽，维持现行项目许可，并针对关键授权条款取得专业审阅，比换名后宣称限制不变更准确。
